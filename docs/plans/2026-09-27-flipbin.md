# FlipBin Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a Flutter PWA for reseller inventory and expense tracking with barcode scanning, local-first storage, and Google Sheets export.

**Architecture:** Flutter Web PWA with Drift (SQLite over IndexedDB) for local persistence, Riverpod for state, `mobile_scanner` for camera barcode scanning, cascading REST APIs for product lookup, and `googleapis` for Google Sheets export. All data lives on-device; the Google Sheet is a manual export target.

**Tech Stack:** Flutter 3.x Web, Dart, Riverpod, Drift, go_router, mobile_scanner, dio, googleapis, google_sign_in

**Spec:** `docs/superpowers/specs/2026-09-27-flipbin-design.md`

## Global Constraints

- Flutter Web only — no native mobile builds. Must run as a PWA in mobile Chrome/Safari.
- Dark mode Material Design theme throughout — deep blue-gray palette per mockups.
- All monetary values stored as `double` with 2-decimal display formatting (no `int` cents).
- Offline-first: every feature except barcode API lookup and Google Sheets sync must work without network.
- Single-user app — no auth for app access, only Google OAuth for Sheets sync.
- Drift code generation via `build_runner` — generated files are `*.g.dart`.
- API call timeout: 5 seconds max.
- Target directory: `flipbin/` under the workspace root.

## Review Focus

1. **Camera permission denial on iOS Safari vs Android Chrome** — the scanner screen must detect denial and show browser-specific instructions, not a blank viewfinder.
2. **IndexedDB storage eviction under storage pressure** — the app must surface the "last synced" timestamp prominently so the user knows how stale their backup is if browser data is cleared.
3. **Barcode strings with leading zeros** — UPCs like `008888511618` must be stored and compared as strings, never parsed to int, or leading zeros are lost.
4. **Concurrent scan + lookup race conditions** — if the user scans a second barcode while the first lookup is in-flight, the UI must show the result for the most recent scan, not the first one to return.
5. **Google Sheets API quota / rate limits** — a full overwrite of 3000+ inventory rows should batch writes (Sheets API allows 10MB per request) and handle 429 responses with retry.

- [ ] **Step 3: Implement `lib/services/barcode_lookup_service.dart`**

  Constructor takes `Dio` and `BarcodeCacheDao`. `lookup()` checks cache first. On miss, tries `https://api.upcdatabase.org/product/{barcode}` (GET, 5s timeout), parses response. On web, uses same-origin `/api/upc` (Vercel serverless → UPCitemdb). On success, saves to cache and returns `BarcodeResult`. On miss/failure, returns null. All barcode values stay as `String` — no numeric conversion.
